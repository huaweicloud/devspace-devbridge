快速入门

创建并托管开发隧道

将本机正在运行的 Web 服务安全地接入 DevBridge，让团队成员在无需部署测试环境的情况下访问和验证你的改动。

预计用时：10 分钟 · 使用 REST API
完成本快速入门后

本地 127.0.0.1:8080 会对应一条有有效期的开发隧道。你可以允许匿名访问，也可以只向持有 connect 令牌的成员开放。

本文内容

  • 创建一条 72 小时的隧道
  • 把本地 8080 端口加入隧道
  • 授权宿主端托管本地服务
  • 向访问者提供受保护的连接

工作原理

开发隧道在本地服务和远程访问者之间建立一条临时通道。DevBridge 管理隧道、端口和权限；RelayService 与隧道网关负责建立连接和转发实际流量。

01本地服务127.0.0.1:8080
托管
02DevBridge 隧道临时地址 + 访问策略
访问
03团队成员浏览器或客户端

隧道不会把源代码或本地文件上传到 DevBridge，只转发已开放端口上的连接。

准备工作

开始前，请确认你具备：

  • 一个可用的 DevBridge 工作空间（namespace）和接入集群（cluster），例如 ns-demo、cn-north-4-bridge。
  • 用于访问 DevBridge API 的客户端证书、私钥和 CA 证书。
  • curl 和 jq。
  • 已经在本机启动的服务。本文假设它监听 127.0.0.1:8080。
  • 已经安装并配置好的 RelayService 客户端。

设置本文会用到的环境变量：

Shell
export DEVBRIDGE_ENDPOINT="https://devbridge-api.example.com"
export DEVBRIDGE_API="$DEVBRIDGE_ENDPOINT/open-api-inner/v1/relay-controller"
export DEVBRIDGE_NAMESPACE="ns-demo"
export DEVBRIDGE_CLUSTER="cn-north-4-bridge"

export DEVBRIDGE_CLIENT_CERT="./client.crt"
export DEVBRIDGE_CLIENT_KEY="./client.key"
export DEVBRIDGE_CA_CERT="./ca.crt"

devbridge_api() {
  curl --fail --silent --show-error \
    --cert "$DEVBRIDGE_CLIENT_CERT" \
    --key "$DEVBRIDGE_CLIENT_KEY" \
    --cacert "$DEVBRIDGE_CA_CERT" \
    -H "X-Namespace: $DEVBRIDGE_NAMESPACE" \
    "$@"
}
从平台获取这些值

namespace 表示你的隔离空间，cluster 表示隧道接入位置。请使用平台分配的值，不要自行猜测或复用其他用户的工作空间。

1. 创建隧道

创建一条名为 local-web 的隧道，并把返回结果保存到环境变量。expiration 的单位是小时：

Shell
TUNNEL=$(devbridge_api \
  -X POST "$DEVBRIDGE_API/tunnels" \
  -H "Content-Type: application/json" \
  -d "{
    \"name\": \"local-web\",
    \"description\": \"Share the local web application\",
    \"clusterId\": \"$DEVBRIDGE_CLUSTER\",
    \"expiration\": 72,
    \"type\": \"bridge\"
  }")

export TUNNEL_ID=$(printf '%s' "$TUNNEL" | jq -r .tunnelId)
export TUNNEL_HOST=$(printf '%s' "$TUNNEL" | jq -r .url)

printf 'Tunnel ID: %s\nTunnel host: %s\n' "$TUNNEL_ID" "$TUNNEL_HOST"

输出类似：

Text
Tunnel ID: km5q7d2a
Tunnel host: km5q7d2a.cn-north-4-bridge.myhuaweicloud.com
TUNNEL_ID
隧道的短标识。查询、更新、配置端口和签发令牌时都会用到。
TUNNEL_HOST
隧道主机名。RelayService 建立宿主连接后，Gateway 才能在该隧道上接收访问请求。
expiration
隧道有效期规格。默认 72 小时，最短 1 小时，最长 720 小时（30 天）。

2. 开放本地端口

隧道默认不开放任何端口。下面把本地 Web 服务使用的 8080 端口加入隧道，并要求访问者提供 connect 令牌：

Shell
devbridge_api \
  -X POST "$DEVBRIDGE_API/tunnels/$TUNNEL_ID/ports" \
  -H "Content-Type: application/json" \
  -d '{
    "port": 8080,
    "protocol": "http",
    "allowAnonymous": false
  }' | jq
设置如何选择
protocol: http本地服务直接接收 HTTP。
protocol: https本地服务自身启用了 HTTPS。
protocol: auto希望数据面自动识别协议。
allowAnonymous: false仅允许持有 connect 令牌的成员访问。
allowAnonymous: true允许任何获得隧道地址的人访问。
公开前先判断内容

本地管理后台、调试接口和包含用户数据的服务不应启用匿名访问。对不确定的场景保持 false。

3. 托管本地服务

宿主端需要一个 host 令牌，证明它有权为这条隧道提供服务。每次请求都会生成新令牌：

Shell
HOST_CREDENTIAL=$(devbridge_api \
  -X POST "$DEVBRIDGE_API/tunnels/$TUNNEL_ID/token?scope=host")

export HOST_TOKEN=$(printf '%s' "$HOST_CREDENTIAL" | jq -r .token)
printf 'Host token expires at: %s\n' \
  "$(printf '%s' "$HOST_CREDENTIAL" | jq -r .expiration)"

在 RelayService 中创建宿主连接时提供以下四项输入：

输入本文示例作用
隧道 ID$TUNNEL_ID选择要托管的隧道。
接入集群$DEVBRIDGE_CLUSTER连接当前区域的隧道网关。
本地地址127.0.0.1:8080指定流量最终转发到哪里。
宿主令牌$HOST_TOKEN授权 RelayService 建立宿主连接。

宿主连接建立成功后保持 RelayService 运行。关闭 RelayService 会中断流量，但不会立即删除隧道配置。

RelayService 启动方式

不同 RelayService 版本可能使用命令行参数或配置文件。按当前客户端的启动说明传入上述四项值；连接成功后，客户端应显示宿主连接状态和 Gateway 提供的最终访问地址。

4. 访问隧道

访问方式取决于端口是否允许匿名访问。

匿名访问

allowAnonymous: true 时，访问者只需要 Gateway 提供的最终访问地址。

受保护访问

allowAnonymous: false 时，访问者还必须携带 connect 令牌。

为受保护访问签发一个新的 connect 令牌：

Shell
CONNECT_CREDENTIAL=$(devbridge_api \
  -X POST "$DEVBRIDGE_API/tunnels/$TUNNEL_ID/token?scope=connect")

export CONNECT_TOKEN=$(printf '%s' "$CONNECT_CREDENTIAL" | jq -r .token)
printf 'Connect token expires at: %s\n' \
  "$(printf '%s' "$CONNECT_CREDENTIAL" | jq -r .expiration)"

把 Gateway 显示的最终访问地址和 CONNECT_TOKEN 通过安全渠道交给访问者。访问端如何携带令牌由 Relay Gateway 或 DevBridge 客户端协议决定。

主机名不是完整访问地址

创建隧道返回的 url 是隧道主机名。不要自行拼接协议、端口或令牌；以宿主连接建立后 Relay Gateway 返回或展示的地址为准。

5. 管理与清理

查看当前空间下仍然有效的隧道：

Shell
devbridge_api \
  "$DEVBRIDGE_API/tunnels?clusterId=$DEVBRIDGE_CLUSTER" \
  | jq '.[] | {
      tunnelId,
      name,
      tunnelExpiration,
      url,
      portCount
    }'

不再需要隧道时主动删除，避免遗留可访问入口：

Shell
devbridge_api \
  -X DELETE "$DEVBRIDGE_API/tunnels/$TUNNEL_ID"

删除隧道会同时移除它的端口策略。已有令牌不能再用于已删除或过期的隧道。

使用规则

  • 一条隧道属于一个工作空间和一个接入集群，不能跨隔离空间访问。
  • 每个工作空间默认最多保留 10 条有效隧道。
  • 隧道默认有效 72 小时，最长 30 天；列表只显示尚未过期的隧道。
  • 隧道有效期和令牌有效期相互独立。令牌过期后可以重新签发，不需要重建隧道。
  • host 与 connect 令牌用途不同，不能互换。
  • 端口未显式加入隧道时默认拒绝访问。
保护凭据

不要把客户端私钥、host 令牌或 connect 令牌写入仓库、日志和工单。令牌响应禁止缓存，使用方也应只在需要的进程内保存。

常见问题

页面应该显示“72 小时”还是持续倒计时？
tunnelExpiration 表示创建时选择的固定规格，应显示“72 小时”或“3 天”。服务端会单独判断实际是否过期。
为什么隧道存在但仍然无法访问？
依次检查端口是否已开放、RelayService 宿主连接是否在线、host 令牌是否有效，以及访问者是否需要 connect 令牌。
关闭本地服务会删除隧道吗？
不会。流量会中断，但隧道和端口策略会保留到主动删除或过期清理。
可以公开调试接口吗？
技术上可以，但不建议。优先保持 allowAnonymous: false，并只向明确的协作者发放短期 connect 令牌。
