快速入门

创建并使用开发隧道

使用 Relay Controller 创建一条临时隧道、声明可访问端口，并为宿主端和连接端签发独立 JWT。

适用于 Relay Controller API v1
内部接口

Relay Controller 是控制面服务，API 通过 mTLS 保护。调用方应是受信任的 RelayService、Relay Gateway 或内部编排服务，而不是浏览器终端用户。

本文内容

  • 准备调用环境
  • 创建隧道并取得访问主机名
  • 配置端口协议和匿名访问策略
  • 签发 host 与 connect 令牌

请求如何流转

01内部调用方namespace + mTLS
控制面
02Relay Controller元数据、端口、JWT
令牌
03Relay 数据面Service + Gateway

Controller 不转发 HTTP、TCP、WebSocket 或 WebTransport 流量。

准备工作

开始前，请准备以下信息：

  • Relay Controller 的 HTTPS 地址。
  • 受服务端信任的客户端证书和私钥，以及签发服务端证书的 CA。
  • 调用方所属的 namespace。
  • 当前 region 下已登记的 clusterId，例如 cn-north-4-bridge。

以下示例使用环境变量，避免在命令历史中重复填写路径：

Shell
export RELAY_CONTROLLER="https://relay-controller.example.com"
export RELAY_API="$RELAY_CONTROLLER/open-api-inner/v1/relay-controller"
export RELAY_NAMESPACE="ns-demo"
export RELAY_CLUSTER="cn-north-4-bridge"
export RELAY_CLIENT_CERT="./client.crt"
export RELAY_CLIENT_KEY="./client.key"
export RELAY_CA_CERT="./ca.crt"

先验证证书和网络是否可用：

Shell
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" \
  --key "$RELAY_CLIENT_KEY" \
  --cacert "$RELAY_CA_CERT" \
  "$RELAY_CONTROLLER/openapi.yaml"
证书校验

不要使用 -k 跳过服务端证书校验。生产环境还应由可信网关提供经过认证的 namespace，避免调用方自行声明其他租户身份。

1. 创建隧道

创建隧道时必须指定名称和 cluster。expiration 是固定规格，单位为小时；默认 72 小时，允许范围为 1 到 720 小时。

Shell
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" \
  --key "$RELAY_CLIENT_KEY" \
  --cacert "$RELAY_CA_CERT" \
  -X POST "$RELAY_API/tunnels" \
  -H "X-Namespace: $RELAY_NAMESPACE" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "local-web",
    "description": "Local web development tunnel",
    "clusterId": "cn-north-4-bridge",
    "expiration": 72,
    "type": "bridge"
  }'

响应直接返回隧道资源，不额外包装 result：

JSON
{
  "name": "local-web",
  "tunnelId": "km5q7d2a",
  "tunnelCode": 277278047059,
  "clusterId": "cn-north-4-bridge",
  "description": "Local web development tunnel",
  "bandwidthUsed": 0,
  "tunnelExpiration": 72,
  "created": 1784606400,
  "url": "km5q7d2a.cn-north-4-bridge.myhuaweicloud.com",
  "type": "bridge"
}
tunnelId
40 位 tunnelCode 的 8 位小写 Base32 表示，用于 API 路径和访问主机名。
tunnelExpiration
创建或更新时选择的有效期规格，单位为小时，不是持续递减的剩余秒数。
url
隧道主机名。最终协议、端口和路由方式由端口策略及 Relay Gateway 决定。

2. 配置端口

端口策略决定 Gateway 如何识别转发协议，以及连接端是否必须携带 connect 令牌。创建端口时三个字段都必填。

Shell
export TUNNEL_ID="km5q7d2a"

curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" \
  --key "$RELAY_CLIENT_KEY" \
  --cacert "$RELAY_CA_CERT" \
  -X POST "$RELAY_API/tunnels/$TUNNEL_ID/ports" \
  -H "X-Namespace: $RELAY_NAMESPACE" \
  -H "Content-Type: application/json" \
  -d '{
    "port": 8080,
    "protocol": "http",
    "allowAnonymous": false
  }'
字段可选值说明
protocolhttp、https、autoauto 由数据面识别实际协议。
allowAnonymoustrue、false为 false 时，连接端需要有效的 connect 令牌。

更新端口时，protocol 和 allowAnonymous 均为可选字段，只提交需要修改的值。

3. 签发连接令牌

每条隧道有两类独立令牌。每次调用都签发一个新 JWT，不复用、不缓存，也不存入 Redis。

host

交给 RelayService，用于声明并托管本地服务。

connect

交给访问端，用于连接禁止匿名访问的端口。

Shell
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" \
  --key "$RELAY_CLIENT_KEY" \
  --cacert "$RELAY_CA_CERT" \
  -X POST "$RELAY_API/tunnels/$TUNNEL_ID/token?scope=host" \
  -H "X-Namespace: $RELAY_NAMESPACE"

curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" \
  --key "$RELAY_CLIENT_KEY" \
  --cacert "$RELAY_CA_CERT" \
  -X POST "$RELAY_API/tunnels/$TUNNEL_ID/token?scope=connect" \
  -H "X-Namespace: $RELAY_NAMESPACE"
JSON
{
  "tunnelId": "km5q7d2a",
  "scope": "host",
  "lifetime": 3600,
  "expiration": 1784610000,
  "token": "eyJ..."
}

lifetime 的单位是秒，取服务端固定配置 relay.jwt.token.ttl-seconds，不随隧道有效期变化。响应带有 Cache-Control: no-store。

令牌安全

令牌是短期凭据。不要写入日志、仓库、URL 参数或前端持久化存储；只把对应 scope 的令牌交给实际使用方。

4. 查询和清理

列表接口只返回当前 namespace 下未过期的隧道，可按 cluster 过滤。响应中的 portCount 便于调用方判断端口策略数量。

Shell
# 查询当前 cluster 的隧道
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" --key "$RELAY_CLIENT_KEY" --cacert "$RELAY_CA_CERT" \
  -H "X-Namespace: $RELAY_NAMESPACE" \
  "$RELAY_API/tunnels?clusterId=$RELAY_CLUSTER"

# 查询单条隧道
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" --key "$RELAY_CLIENT_KEY" --cacert "$RELAY_CA_CERT" \
  -H "X-Namespace: $RELAY_NAMESPACE" \
  "$RELAY_API/tunnels/$TUNNEL_ID"

# 物理删除隧道及其端口策略
curl --fail --silent --show-error \
  --cert "$RELAY_CLIENT_CERT" --key "$RELAY_CLIENT_KEY" --cacert "$RELAY_CA_CERT" \
  -X DELETE -H "X-Namespace: $RELAY_NAMESPACE" \
  "$RELAY_API/tunnels/$TUNNEL_ID"

删除是物理删除。过期隧道不会出现在列表中，并在保留期后由老化任务清理。

API 概览

所有 namespace 范围内的接口都必须携带 X-Namespace。完整字段和约束以 OpenAPI YAML 为准。

方法路径用途
POST/tunnels创建隧道
GET/tunnels列出当前 namespace 的隧道
GET/tunnels/{tunnelId}查询隧道详情
PUT/tunnels/{tunnelId}更新隧道
DELETE/tunnels/{tunnelId}删除隧道
POST/tunnels/{tunnelId}/token?scope=签发 host 或 connect 令牌
POST/tunnels/{tunnelId}/ports创建端口策略
GET/tunnels/{tunnelId}/ports列出端口策略
PUT/tunnels/{tunnelId}/ports/{port}更新端口策略
DELETE/tunnels/{tunnelId}/ports/{port}删除端口策略

上述路径均相对于 /open-api-inner/v1/relay-controller。Gateway 端口策略查询和 metering 是服务间接口，不属于本快速入门的调用链。

错误处理

参数错误返回 4xx，服务内部错误返回 5xx。错误响应统一使用 error 对象：

JSON
{
  "error": {
    "code": "40000",
    "message": "request validation failed",
    "target": "request",
    "details": [
      {
        "code": "40000",
        "target": "expiration",
        "message": "must be less than or equal to 720"
      }
    ]
  }
}

调用方应先根据 HTTP 状态码区分请求问题和服务问题，再使用 error.code 做稳定分支。message 用于诊断，不建议作为程序判断条件。

业务边界与约束

  • 一个 Relay Controller 实例只管理配置 region 下的 cluster，不信任跨 region 的 cluster 数据。
  • 每个 namespace 默认最多拥有 10 条有效隧道；过期和已删除记录不占配额。
  • namespace、clusterId 和 tunnelId 会参与隔离校验，调用方不能只凭 tunnelId 访问资源。
  • Relay Controller 只管理控制面；连接数、实时上传和下载速率需要数据面上报，本版不在隧道列表中展示。
  • metering 接口已预留，但本期未对接，不应作为计费依据。
  • 多副本部署时，流控和 namespace 配额需要由 Redis 或网关提供一致性；单机内存计数只能作为实例级保护。
